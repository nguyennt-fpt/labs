Prerequisites

1. An AWS GPU instance

The model needs a GPU with about 10 GB of memory. The project uses:

SettingValue
Instance typeg4dn.xlarge (NVIDIA Tesla T4 16 GB, 4 vCPU, 16 GB RAM)
AMIUbuntu Server 24.04 LTS (or the Deep Learning Base OSS Nvidia Driver GPU AMI, which has the driver preinstalled)
Storage50 GB gp3 (the model alone is ~9 GB)
Regionany region with g4dn capacity (the project used us-east-1)

New AWS accounts often have a vCPU quota of 0 for G instances. Request an increase for “Running On-Demand G and VT instances” (at least 4 vCPUs) in Service Quotas before you start; approval can take a while.

Cost: an on-demand g4dn.xlarge is roughly 0.5 USD per hour in us-east-1. Stop the instance whenever you are not using it — a stopped instance only costs the disk.

2. Security group

Open only what you need, and only to your own IP:

Inbound rules:
  SSH    22    <YOUR_IP>/32
  HTTP   80    <YOUR_IP>/32     # DVWA through Nginx
  Custom 5000  <YOUR_IP>/32     # dashboard

Outbound: all traffic (to pull images, rules and the model)

Never open port 80 to 0.0.0.0/0. DVWA is vulnerable on purpose; anyone who reaches it can run commands on the box.

Home internet IPs change. If SSH suddenly times out, check that your current IP (curl https://checkip.amazonaws.com) is still the one in the security group.

3. An SSH key pair

Create or choose a .pem key pair when launching the instance and keep it outside any git repository (or make sure *.pem is in .gitignore).

On Windows, the built-in OpenSSH may refuse the key with “UNPROTECTED PRIVATE KEY FILE”. The ssh that ships with Git for Windows (Git Bash) does not have this problem.
